# Design Spec: SQL-First Senior-Level Active Analyst

## 1. Objective
Transform the DNA Desktop Assistant's data engine from a basic table/summary describer into an active, senior-level data analyst. The assistant must run advanced DuckDB SQL queries to uncover business insights using both ratios (percentages) and volumes (totals), and present senior-level findings in both deep reports and voice-only interactions.

---

## 2. Core Concepts & Senior-Level Logic

Senior-level data analysis differs from junior-level reporting in two main areas:
1. **Volume and Scale Context**: A 100% churn rate in a cohort of 2 customers is statistically insignificant. A 40% churn rate in a cohort of 3,000 customers is a major business crisis. DNA must calculate the share of total volume to prioritize high-impact findings.
2. **Business Impact Translation**: Instead of listing column statistics, the engine translates findings into actionable insights (e.g., identifying the "perfect storm" segments where multiple risk factors overlap).

---

## 3. Component Details & DuckDB SQL Queries

### A. Target-Aware Profiling Extension (`skills/data_engine/profiler.py`)
When a target column is detected in a dataset (e.g., `Churn`, `Attrition`, `Purchased`):
1. **Identify the Positive Class**: E.g., `'Yes'`, `1`, `True`.
2. **Calculate Overall Baseline**:
   * Total Rows ($N_{total}$)
   * Total Target Rows ($N_{target}$)
   * Baseline Rate ($R_{baseline} = N_{target} / N_{total}$)
3. **Execute Categorical Target Cross-Tabulation**:
   For each categorical column (cardinality between 2 and 12), run the following query:
   ```sql
   SELECT 
       "{column}" AS category,
       COUNT(*) AS total_count,
       SUM(CASE WHEN "{target_col}" = '{positive_val}' THEN 1 ELSE 0 END) AS event_count,
       (AVG(CASE WHEN "{target_col}" = '{positive_val}' THEN 1.0 ELSE 0.0 END) * 100) AS event_pct,
       (COUNT(*) * 100.0 / {dataset_total_rows}) AS pct_of_dataset,
       (SUM(CASE WHEN "{target_col}" = '{positive_val}' THEN 1 ELSE 0 END) * 100.0 / {dataset_total_target}) AS pct_of_total_events
   FROM data_table
   GROUP BY "{column}"
   ORDER BY total_count DESC;
   ```
   *This SQL returns:*
   - The size of each group (`total_count` and `% of dataset`)
   - The number of target events within each group (`event_count`)
   - The rate of target events (`event_pct`)
   - The group's contribution to the total problem (`pct_of_total_events`)

4. **Execute Numeric Cohort Profiling**:
   For numeric columns, group by the target variable to compare means, standard deviations, and totals:
   ```sql
   SELECT 
       "{target_col}" AS target_status,
       AVG("{num_col}") AS mean_val,
       SUM("{num_col}") AS total_val
   FROM data_table
   GROUP BY "{target_col}";
   ```

### B. Upgraded Analyst Insights Prompt (`skills/data_engine/analyst.py`)
We will modify the prompt used by `DataAnalyst` to instruct the LLM to write like a senior business intelligence director.

*   **Prompt Instructions**:
    *   *“Analyze both the rate (%) and the absolute volume (total count) to separate statistical noise from actual business impact.”*
    *   *“Always point out which segment accounts for the largest share of the problem (e.g., 'Category X accounts for 85% of all defaults').”*
    *   *“Avoid reading raw column statistics. Focus on why this is happening, what the business impact is, and provide concrete, prioritized recommendations.”*

---

### C. Voice Summarization Integration (`skills/data_engine/__init__.py`)
When a general summary is requested via voice:
1. Run the `DataProfiler` and `PatternDetector` to identify the schema, target column, and anomalies.
2. If a target column is present, run the `DataAnalyst` in the background with the SQL-generated breakdowns.
3. Return the `executive_summary` generated by the LLM as the voice response. This ensures the user hears a senior-level analysis (incorporating volumes and business impact) instead of a raw description of columns.

---

## 4. Implementation Steps

1. **Step 1**: Update `PatternDetector` in `detector.py` to identify the positive class value for detected binary targets.
2. **Step 2**: Update `DataProfiler` in `profiler.py` to run target breakdown queries in DuckDB and store the results in the profile dictionary under `target_breakdowns`.
3. **Step 3**: Update `DataAnalyst` in `analyst.py` to format `target_breakdowns` into the LLM prompt and enforce senior-level reporting rules.
4. **Step 4**: Integrate the analyst executive summary into `run_analysis` for `VOICE_ONLY` general summaries in `__init__.py`.
5. **Step 5**: Run tests to verify that both the console log reports and the voice responses are rich, volume-informed, and highly professional.
